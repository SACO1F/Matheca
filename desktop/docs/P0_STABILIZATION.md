## 本轮实现

### 1. 统一便携版验证入口

新增 `scripts/validate-portable.mjs`：

- `npm run test:portable`：核心 9 个专项。
- `npm run test:portable:full`：完整 21 个专项。
- 默认使用 `releases/latest.txt` 的实际 EXE，支持 `--exe` 指定、`--list` 列出清单。
- `--only 脚本名` 可在套件内复核指定项目，原失败报告不会被覆盖。
- 限定项目支持的 Node 版本，使用同一 Node 执行子脚本；串行运行避免窗口焦点竞争。
- 每次生成单独 `test-output/validation-时间-进程号/REPORT.md`，记录北京时间、EXE/SHA256、系统/Node、退出码、耗时、日志和新建数据目录。
- 单项失败返回非零；超时或中断停止后续测试，不终止用户正常应用。

新增 `format:check`。完整接口套件需要 OpenSSL 与装有 reportlab/Pillow 的 Python，可用 `MATHECTOR_QA_PYTHON` 指定。旧专项中部分 OpenSSL 路径仍为 Git for Windows 默认路径。

### 2. 题卡测量与快捷按钮

`MasonryCards` 将 React 布局通知与 ResizeObserver 通知合并进同一 requestAnimationFrame；尺寸、选中和内容均未改变时提前返回，避免菜单/toast 等无关重渲染反复清理样式和重算 Grid 行跨度。

保留原有 CSS Grid、自然高度测量、滚动定位、卡片展开动画与减少动态效果，没有替换为虚拟列表。

底部为快捷加号预留 88px 操作区，将其与可滚动题卡分开。题集选择/文档预览临时隐藏加号时仍保留该区域，防止三列高度跳变；校对和历史页面不占用该区域。最小窗口与模拟 DPI 几何断言检查滚动区不伸进加号区域。

性能脚本改为 100 张混合文字/公式/图片题卡，连续 20 次开关，分别记录展开/收起各 10 次的 P50/P95、长帧与最长帧；另检查快速反转、20 次校对往返、减少动态效果，以及 100%/125%/150%/200% 模拟 DPI。

### 3. 恢复与文件发布安全

- 恢复必须创建新的目标目录，拒绝复用已有目录，防止后续回滚误删已有原图。
- 恢复复制题目对象后再改来源路径，失败不会污染原备份对象，可直接重试。
- ZIP 文件源异步错误转入 pipeline，原图在备份期间消失时正常失败、清理临时文件，保留上一次备份。
- PDF/Word 与 ZIP 最终发布共用 `publishFile`：关闭写入后 fsync 临时文件，再 rename 到目标，失败不会提前替换原目标。
- 磁盘不足、文件占用/权限失败给出可恢复提示；不把模拟注入当作真实磁盘耗尽或物理断电验证。
- 数据库初始化/迁移失败时关闭连接，保留迁移保护副本，便于恢复。
- 操作已经成功但业务历史写入失败时，仍返回真实操作结果；记录失败也不会掩盖原本的磁盘错误。

新增 `tests/recovery.test.ts`：目录复用保护、数据库写满回滚、重试、旧备份保留、文件发布失败、刷盘失败、异步原图丢失、失败迁移保护副本及错误提示。

新增 `scripts/recovery-ui.mjs`：真实新 EXE 下的取消/关闭/损坏/同 ID 冲突备份；历史写入故障；仅终止隔离测试应用；另终止持有未提交 SQLite 事务的独立测试写入进程；重新启动验证已提交内容、完整性与未提交目录清理。

## 最终包性能测量

同一机器、同一脚本，100 张混合文字/公式/图片题卡，开关共 20 次，每种方向各 10 次。P95 使用样本的最近秩计算；小样本与系统负载会产生波动，不能视为所有机器的保证。

| 指标                        | 修改前：展开 | 最终包：展开 | 修改前：收起 | 最终包：收起 |
| --------------------------- | ------------ | ------------ | ------------ | ------------ |
| 布局 P50                    | 24ms         | 12ms         | 23ms         | 11ms         |
| 布局 P95                    | 32ms         | 16ms         | 31ms         | 14ms         |
| 超过 50ms 的帧（10 次合计） | 21           | 20           | 20           | 20           |
| 最长帧                      | 221ms        | 129ms        | 208ms        | 133ms        |

布局工作量与最长帧下降，但长帧数量没有明显下降，仍有卡顿优化空间，不能宣称稳定满帧。布局测量优化和操作区调整共同参与该结果，不能只归因于某一行代码。

最终包通过 20 次校对往返、快速开关与最终几何、减少动态效果，以及最小窗口 100%/125%/150%/200% 模拟 DPI 的遮挡/横向溢出检查。

修改前日志：`test-output/p0-performance-before.log`。最终数据：`test-output/validation-2026-10-15T07-02-32-791Z-15392/sidebar-performance-ui.log`。
